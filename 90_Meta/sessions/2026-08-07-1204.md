# Podsumowanie Sesji — 2026-08-07 12:04

## 💡 Wykonany audyt i poprawki
Przeprowadzono pełny przegląd notatki [[1.1-ideation-fr-nfr]] w poszukiwaniu nieuargumentowanych terminów technicznych i czysto akademickich wzorów:

1. **Sekcja 3.2 (MoSCoW Rules):**
   - Dodano **Test Ścieżki Krytycznej (Critical Path Test)**.
   - Określono ścisłe limity budżetów czasowych (MUST ≤ 60%, SHOULD ~20-30%, COULD ≤ 10%, WON'T 0%).

2. **Sekcja 6.2 (Feasibility & Estymacja):**
   - Dodano pojęcie **Mnożnika Ryzyka (Risk Multiplier)** dla urealnienia estymacji (znany stack ×1.2, nowa baza ×1.5, customowe/zewnętrzne API ×2.0).

3. **Sekcja 7.2 (Latency Budget w Praktyce):**
   - Rozbudowano tabelę o konkretne narzędzia pomiarowe (DevTools Network Tab, `curl`, `EXPLAIN ANALYZE`, V8 profiler).
   - Wprowadzono nagłówek HTTP `Server-Timing: db;dur=110, auth;dur=25` do bezpośredniej wizualizacji w Chrome DevTools.

4. **Sekcja 7.4 (Dostępność i Dziewiątki Availability):**
   - Przełożono abstrakcyjny wzór MTBF/MTTR na konkretne dziewiątki (99% = 7.2 h/mc, 99.9% = 43 min/mc, 99.99% = 4.3 min/mc) i wskazano wymagania architektoniczne dla każdej opcji.
